# SurfaceImpact / DestructionPolicy

Run `python MCCodeCampLibrary/tests/run_surface_impact.py` from repository root. This compiles the actual production classes with Java 22 against `target/editor-classpath.txt` and executes API-boundary doubles; it is not a live Paper or full Maven test.

Coordinator contract:
- Gate requests through `DestructionPolicy` and finish the full-height +/-90-block backup before constructing `SurfaceImpact`.
- Call `tick()` from the existing synchronous owner; there are no internal tasks/listeners.
- Only forward approved first-50-block MeteorVisuals callbacks to `enqueueBurn(translatedPosition, radius)`. SurfaceImpact independently rejects foreign-world/nonfinite positions and horizontal distance beyond 50 (one-millionth-block tolerance). Radius clamps to 1..5.
- Native grid explosions use radius 30, spacing `7/sqrt(3)` rounded to unique block-column offsets (approximately triple area density, not triple linear density), and doubled power 6.4. One additional central power-30 explosion runs first, followed by the entire grid in the SAME synchronous tick, once only. The grid still includes its own central power-6.4 explosion. All use breakBlocks=true, source=null, setFire=false. Ground scanning ignores canopy and trunks; columns without ground are skipped.
- This deliberately creates a heavy single-tick CPU spike and can stall the server. There is no explosion pacing, additional scheduler, or asynchronous world mutation.
- Queued burn columns merge vertical spans and deduplicate until processed; 128 columns/tick share a budget with post-grid central random scars. Direct edits stay within the backup square. Fires use normal physics; no spread listener or gamerule changes exist. Native explosion and natural fire effects are not sandboxed by that direct-edit bound.
- BEFORE ANY explosion, a whole-batch chunk preflight covers the center +/-68 square (power30 conservative native reach60 + margin8; the grid's radius30 + power6.4 reach12.8 + margin8 is smaller). An unloaded required chunk pauses the whole blast and queued tick mutations, never a partial grid. This direct-blast envelope fits inside the required full-height +/-90 backup. It is not a claim that subsequent natural fire spread has a finite sandbox. Unloaded burn requests reject. No tick calls loadChunk/getChunkAt. Ground and entity operations remain synchronous.
- Post-blast scars now cover radius24 (previously12), select 60% of eligible exposed stone-like columns (previously24%), and replace 1..3 contiguous stone-like layers with magma/blackstone. Stop at a non-stone layer or world minimum; preserve non-stone surfaces. Scars remain random rather than blanket replacement and share the existing 128-column tick budget with burns.
- Cancel before restore/disable; cancellation clears queues and prevents all subsequent edits. Counters remain available, counting direct writes, attempted native explosions, and unique directly ignited entities (not secondary spread/explosion writes).
- Live permission is volatile, exact `world`, explicit start within one horizontal block of (-1368,3350), armed only. Native entity damage gate allows radius 90 while armed. Exact `testworld` is the only default. Disarm in final cleanup; do not persist the flag.

Boundary coverage: exact/fail-closed policy, disarm/recreation, grid uniqueness/radius/approximately-threefold density, same-tick once-only central30 plus grid6.4/source/ground selection, outer required-chunk preflight with zero early explosions, deterministic larger/denser/deeper partial scars, stone-only layers and radius/depth limits, translated foliage/fire writes, helper exclusions versus players/items, first-50 rejection, cross-world rejection, merged duplicate batches and 128-column budget, main-thread guard, cancellation before first tick and retained telemetry. Real Paper explosion/fire behavior and backup restoration require separately authorized live verification. No deployment is performed by this test.
