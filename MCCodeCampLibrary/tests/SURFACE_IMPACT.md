# SurfaceImpact / DestructionPolicy

Run `python MCCodeCampLibrary/tests/run_surface_impact.py` from repository root. This compiles the actual production classes with Java release 22 against `target/editor-classpath.txt` and executes API-boundary doubles; it is not a live Paper or full Maven test. Alternatively set `SURFACE_IMPACT_CLASSPATH` to the Paper 1.21.11 API and its runtime dependencies. Temporary compilation uses the platform temporary directory (`TMPDIR` is respected), not a hard-coded Windows path.

Coordinator contract:
- Gate requests through `DestructionPolicy` and finish the full-height +/-90-block backup before constructing `SurfaceImpact`.
- Call `tick()` from the existing synchronous owner; there are no internal tasks/listeners.
- Only forward approved first-50-block MeteorVisuals callbacks to `enqueueBurn(translatedPosition, radius)`. SurfaceImpact independently rejects foreign-world/nonfinite positions and horizontal distance beyond 50 (one-millionth-block tolerance). Radius clamps to 1..5.
- No native terrain explosions are created. A block-centered sphere at the supplied impact location has a radius30 guaranteed core and coordinate-noisy radius30..34 shell. Removal ignores blast resistance but preserves negative-hardness materials (bedrock, barriers, other unbreakables). It removes liquids/foliage too; it is intentionally not native explosion simulation, loot generation, or entity damage.
- Each tick has a shared 4096-cell budget: crater candidate cells (including air/outside/world-height skips), conservative burn neighbour lookup reservations, and resumable scar ground scans/layers all consume it. Burns use at most half so the crater progresses. No asynchronous world access, internal scheduler, or up-front volume allocation exists. This bounds work, not milliseconds or Paper lighting/client packet cost.
- Queued burn columns merge unprocessed vertical spans and deduplicate; at most128 queued burn/scar columns are visited per tick. A tall merged span resumes next tick. All direct writes use `setType(material, false)` to avoid bulk physics cascades and stay within the +/-90 backup square. Natural fire spread is not intercepted or gamerule-modified and is not sandboxed by the direct-edit bound.
- Crater work checks the current cell's chunk and retries that cell when unloaded. Unlike the removed blast batch, already-loaded sections may be edited before a later missing chunk pauses progress. Burns/scars check their column and one-block neighbour margin. Unloaded burn requests reject. No tick calls loadChunk/getChunkAt. Ground and entity operations remain synchronous.
- Post-crater scars cover radius24, select 60% of eligible exposed stone-like columns, and replace 1..3 contiguous stone-like layers with magma/blackstone. Ground scans ignore canopy/trunks, resume within the shared cell budget, and stop at the world minimum. Non-stone surfaces/layers are preserved. Newly exposed crater stone can be scarred.
- Cancel before restore/disable; cancellation clears queues and prevents all subsequent edits. Counters remain available: `changedBlocks()` counts direct writes, `explosions()` is retained and returns zero, and `burnedEntities()` counts unique directly ignited entities (not natural spread).
- Live permission is volatile, exact `world`, explicit start within one horizontal block of (-1368,3350), armed only. Native entity damage gate allows radius 90 while armed. Exact `testworld` is the only default. Disarm in final cleanup; do not persist the flag.

Boundary coverage: fail-closed policy, disarm/recreation, no native explosion calls, multi-tick completion, 4096-read ceiling including tall-world ground scans, spherical core/boundary and partial noisy shell, unbreakables, mixed post-crater scars, translated foliage/fire, helper exclusions versus players/items, first-50 rejection, cross-world rejection, merged duplicate burns, unload/resume, main-thread guard, cancellation before/during crater, and retained telemetry. Live Paper lighting/physics/fire behavior, timings and backup restoration require separately authorized live verification. No deployment is performed by this test.
